# Harness Integration

How to set up an AWM workspace so that **Claude Code** and **OpenCode** — whether spawned by AWM or launched manually inside a scope directory — load the right context docs and see the registered MCP catalog.

Two harnesses are supported as first-class peers:

- **Claude Code** (`claude` CLI) — Anthropic's official CLI; auto-loads `AGENTS.md` walking up from cwd. Per-scope `.awm/context.md` is injected via a user-level `SessionStart` hook (see §3).
- **OpenCode** (`opencode` CLI) — reads `AGENTS.md` walking up from cwd; per-scope `.awm/context.md` is loaded via the `instructions` field in a per-scope `mcp-opencode.json` (see §4).

## 1. Context layers (workspace → agents → scope → session)

| Layer | File | Purpose | Source |
|---|---|---|---|
| Workspace | `<workspace>/WORKSPACE.md` | Universal structural orientation for every scope agent (paths, MCP tools, scope lifecycle, startup ritual) | Committed; hand-maintained |
| Agents (awm-internal) | `<cwd>/AGENTS.md` | AWM-internal architecture (Service Hub, vertical-stripe component dev). Lives at the workspace root, but reaches awm-dev scopes (`projects/awm/*`) for free via .bare-worktree sharing. | Committed; hand-maintained |
| Scope | `.awm/context.md` | Per-scope ritual and architecture brief | Generated by `awm scope create`; gitignored |
| Sessions | `.awm/history.md`, `.awm/artifacts.md` | DB-rendered session logs + sibling-scope artifacts | Regenerated by `awm_refresh` |

How each layer reaches the agent (Claude Code path):

A user-level `SessionStart` hook runs `awm context emit --cwd "$CLAUDE_PROJECT_DIR"`, which walks up from cwd to find the workspace root (marked by `WORKSPACE.md`) and emits **in general → specific order**:

```
<workspace-context path="…/WORKSPACE.md">
…WORKSPACE.md body…
</workspace-context>
<agents-context path="AGENTS.md">                  ← only if <cwd>/AGENTS.md exists
…AGENTS.md body…                                       AND cwd != workspace_root
</agents-context>
<scope-context path=".awm/context.md">             ← only if .awm/context.md exists
…context.md body…
</scope-context>
```

The cwd-only AGENTS.md rule combined with the `cwd != workspace_root` guard routes awm-internal docs to awm-dev scopes naturally (those scopes' `./AGENTS.md` IS the workspace's, via .bare share), without leaking the file into non-awm contexts. Non-awm projects can opt in to per-project orientation by placing their own `AGENTS.md` at the scope root.

OpenCode path: `.awm/mcp-opencode.json` (per-scope, written by `_write_scope_opencode_config`) includes `instructions: [".awm/context.md"]`, which opencode resolves on startup. OpenCode natively walks `AGENTS.md` and `WORKSPACE.md` (treating both as `AGENTS.md`-equivalent rules files in some configurations), so the 3-tier shape carries over.

History/artifacts are deliberately NOT auto-injected (too large). Agents fetch on demand via `awm_refresh` + Read.

> **Legacy artifacts to avoid**: scope-level `AGENTS.md` generated from a template, `CLAUDE.md` symlinks to `AGENTS.md`, and `@.awm/context.md` import lines appended to `AGENTS.md` are all from a pre-2026-05-28 wiring that's been reversed. `awm scope heal` removes them (see §7).

## 2. MCP catalog (registered, advertised even when down)

The canonical MCP registry is `<workspace>/.mcp.json`. AWM fans it out to backend-specific files via the **exporter framework** at `awm/exports/`:

| Exporter | Output | Consumer |
|---|---|---|
| `claude-spawn` | `<workspace>/.awm/spawn-mcp.json` | claude subprocesses launched by AWM (`--strict-mcp-config`) |
| `opencode` | `<workspace>/.awm/mcp-opencode.json` | opencode subprocesses launched by AWM (via `OPENCODE_CONFIG`) — also the base that per-scope `mcp-opencode.json` files overlay `instructions` onto |

Trigger a re-sync from a running agent with the `awm_mcp_sync` MCP tool, or restart `awm-exposed.service` (the lifespan hook calls `sync_mcp_configs()` on startup).

**Registration semantics**: every server listed in `.mcp.json` is *advertised* to spawned agents regardless of whether the upstream service is currently running. The agent will see the tool surface; calls fail with a clear error when the service is down. This makes service availability discoverable (an agent knows `chrome-devtools` *exists* even if the Chrome instance hasn't been started yet).

### Adding a new MCP

1. Append the server block to `<workspace>/.mcp.json` (stdio: `command`/`args`/`env`; HTTP: `url`/`type`).
2. Call `awm_mcp_sync` MCP tool — both backends regenerate.
3. New agent spawns pick it up. Already-running agents must reconnect.

See `skills_get path="tools/mcp.md"` for the per-server fields and the `tools/chrome-devtools.md` / `tools/plotly.md` / etc. for service-specific notes.

## 3. External setup — Claude Code

Required:

- `claude` CLI on `PATH` (Anthropic's `claude-code` package).
- Global Claude Code instructions at `~/.claude/CLAUDE.md` — tell the agent how to orient in any directory it lands in (read AGENTS.md walk-up, etc.).
- **`SessionStart` hook in `~/.claude/settings.json`** that injects scope context:

```jsonc
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup",
        "hooks": [
          {
            "type": "command",
            "command": "cd <workspace> && <conda-env>/bin/awm context emit --cwd \"$CLAUDE_PROJECT_DIR\""
          }
        ]
      }
    ]
  }
}
```

`awm context emit` exits silently with no output if cwd is outside any AWM workspace (no `WORKSPACE.md` upstream) and each individual layer is silently skipped if its file is missing, so the hook is safe in non-scope directories and never blocks session start.

Externally-launched claude in a scope dir auto-loads:

```
~/.claude/CLAUDE.md                          (harness-global)
<workspace-context> ... WORKSPACE.md ...     (SessionStart hook; universal)
<agents-context> ... AGENTS.md ...           (SessionStart hook; cwd-local AGENTS.md only)
<scope-context> ... .awm/context.md ...      (SessionStart hook; per-scope ritual)
```

Note: Claude Code's native `AGENTS.md` walk-up is NOT how these get loaded — Claude Code walks `CLAUDE.md`, not `AGENTS.md`. The SessionStart hook is the sole injection surface; that's why the walk-up + 3-tier emit lives in `awm context emit`.

## 4. External setup — OpenCode

Required:

- `opencode` CLI on `PATH` (npm: `@opencode/cli` or equivalent).
- MCP config at `~/.config/opencode/opencode.jsonc` pointing at the local `awm-mcp` proxy:

```jsonc
{
  "mcp": {
    "awm": {
      "type": "local",
      "enabled": true,
      "command": ["/home/<you>/lib/miniforge3/envs/awm/bin/awm-mcp"],
      "environment": {
        "AWM_WORKSPACE": "/home/<you>/agentic_workspace",
        "AWM_EXPOSED_HOST": "127.0.0.1",
        "AWM_EXPOSED_PORT": "12100"
      }
    }
  },
  "instructions": [".awm/context.md"]
}
```

The `instructions: [".awm/context.md"]` line is the equivalent of Claude Code's SessionStart hook — opencode resolves the relative path against cwd and loads the file as additional system instructions.

For the full MCP catalog (chrome-devtools, ollama, …) in opencode, set `OPENCODE_CONFIG=<workspace>/.awm/mcp-opencode.json` in the shell that launches opencode — that file is the fan-out of the canonical `.mcp.json` produced by `awm_mcp_sync`.

## 5. AWM-spawned agents

AWM launches agents via rooms — `room_create scopes=[…]` or `room_invite scope=…`. The harness is per-session, persisted on the `agent_sessions.agent_cli` column. Default is `claude`.

To spawn an opencode worker:

```
room_create topic="…" scopes=["proj/scope"] agent_cli="opencode"
```

AWM constructs the argv (`opencode run --format json --dir <wd> [--dangerously-skip-permissions] [--model …]`) and sets `OPENCODE_CONFIG` to the **per-scope** `.awm/mcp-opencode.json` if it exists (fallback: workspace-level cfg). The per-scope file overlays `instructions: [".awm/context.md"]` on top of the workspace MCP catalog.

The spawn picks up:

- **MCP catalog** via `--strict-mcp-config --mcp-config <workspace>/.awm/spawn-mcp.json` (claude) or `OPENCODE_CONFIG` (opencode).
- **Workspace + project context** via the harnesses' native `AGENTS.md` walk-up.
- **Scope context** via the same mechanisms as external sessions — the `SessionStart` hook fires for spawned claudes too (it lives in user-level `~/.claude/settings.json`), and the per-scope `mcp-opencode.json` carries `instructions` for opencode.
- **Permission mode** — `bypassPermissions` by default for worker scopes, configurable per session.

## 6. Verifying setup

```bash
# 1. SessionStart hook installed
jq '.hooks.SessionStart' ~/.claude/settings.json

# 2. context emit works in a scope
cd <workspace>/projects/<p>/<scope>
awm context emit --cwd "$PWD"   # should print <scope-context>…</scope-context>

# 3. MCP fan-out produced
awm-mcp call awm_mcp_sync       # or call the tool from an agent
ls <workspace>/.awm/spawn-mcp.json <workspace>/.awm/mcp-opencode.json

# 4. Externally-launched claude sees scope context
cd <workspace>/projects/<p>/<scope> && claude -p "/context"
# look for <scope-context path=".awm/context.md"> in the loaded context

# 5. Externally-launched opencode sees scope context
cd <workspace>/projects/<p>/<scope> && opencode run "list your loaded instructions"

# 6. AWM-spawned opencode worker
awm room create --topic "test" --scope myproj/myscope --agent-cli opencode
```

## 7. Maintenance

Updating any of these files is part of the same edit cycle as the code that surfaced the need (stack change, new MCP, new convention). The `awm/debrief.md` skill enforces this: step 1 is "update AGENTS.md if user-facing behavior changed."

**`awm scope heal`** is the cleanup pass — it enforces the canonical tier-3 = `.awm/` only shape across all active scope worktrees:

- strips trailing `@.awm/context.md` import lines from tracked `AGENTS.md`
- deletes scope-local `AGENTS.md` if untracked (template chrome from the legacy wiring)
- deletes `CLAUDE.md` if it's a symlink to `AGENTS.md` or otherwise untracked
- back-fills `.awm/context.md` if missing

Idempotent. Use `awm scope heal --dry-run` to preview.
