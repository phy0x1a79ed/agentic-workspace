# Harness Integration

How to set up an AWM workspace so that **Claude Code** and **OpenCode** — whether spawned by AWM or launched manually inside a scope directory — load the right context docs and see the registered MCP catalog.

Two harnesses are supported as first-class peers:

- **Claude Code** (`claude` CLI) — Anthropic's official CLI; auto-loads `CLAUDE.md` walking up from cwd and resolves recursive `@<path>` imports inside it.
- **OpenCode** (`opencode` CLI) — reads `AGENTS.md` walking up from cwd; MCP servers configured via `~/.config/opencode/opencode.jsonc` or `OPENCODE_CONFIG`.

## 1. Context layers (workspace → scope → session)

| Layer | File | Purpose | Source |
|---|---|---|---|
| Workspace | `<workspace>/AGENTS.md` + `<workspace>/CLAUDE.md` (symlink) | Orchestrator persona + workspace ritual (`awm_status`, `inbox_search`, `scope_list`, `lock_list`) | Committed; hand-maintained |
| Project | `projects/<p>/<scope>/AGENTS.md` + `CLAUDE.md` (symlink) | Project-specific stack, env, conventions | Templated by `awm project create` |
| Scope | `.awm/context.md` | Per-scope ritual — pulled into AGENTS.md via `@.awm/context.md` import | Generated by `awm scope create` |
| Sessions | `.awm/history.md`, `.awm/artifacts.md` | DB-rendered session logs + sibling-scope artifacts | Regenerated by `awm_refresh` |

The wiring that makes the layers auto-load:

1. **CLAUDE.md → AGENTS.md symlink at each level**. Claude Code walks up from cwd looking for `CLAUDE.md`. OpenCode reads `AGENTS.md` natively. Pointing one at the other means a single source-of-truth.
2. **`@.awm/context.md` import line at the bottom of every scope's AGENTS.md**. Claude Code resolves `@<path>` recursively; OpenCode reads it too (as text content of AGENTS.md). So `.awm/context.md` rides along even though no harness auto-loads it on its own.
3. **Workspace root has both `AGENTS.md` and `CLAUDE.md`** — externally-launched claude/opencode at workspace root load the orchestrator persona automatically.

Run `awm scope heal` after upgrading to back-fill the symlinks and import line on existing scopes.

## 2. MCP catalog (registered, advertised even when down)

The canonical MCP registry is `<workspace>/.mcp.json`. AWM fans it out to backend-specific files via the **exporter framework** at `awm/exports/`:

| Exporter | Output | Consumer |
|---|---|---|
| `claude-spawn` | `<workspace>/.awm/spawn-mcp.json` | claude subprocesses launched by AWM (`--strict-mcp-config`) |
| `opencode` | `<workspace>/.awm/mcp-opencode.json` | opencode subprocesses launched by AWM (via `OPENCODE_CONFIG`) |

Trigger a re-sync from a running agent with the `awm_mcp_sync` MCP tool, or restart `awm-exposed.service` (the lifespan hook calls `sync_mcp_configs()` on startup).

**Registration semantics**: every server listed in `.mcp.json` is *advertised* to spawned agents regardless of whether the upstream service is currently running. The agent will see the tool surface; calls fail with a clear error when the service is down. This makes service availability discoverable (an agent knows `chrome-devtools` *exists* even if the Chrome instance hasn't been started yet).

### Adding a new MCP

1. Append the server block to `<workspace>/.mcp.json` (stdio: `command`/`args`/`env`; HTTP: `url`/`type`).
2. Call `awm_mcp_sync` MCP tool — both backends regenerate.
3. New agent spawns pick it up. Already-running agents must reconnect.

See `skills_get path="tools/mcp.md"` for the per-server fields and the `tools/chrome-devtools.md` / `tools/plotly.md` / etc. for service-specific notes.

## 3. External setup — Claude Code

Required:

- `claude` CLI on `PATH` (Anthropic's `claude-code` package).
- Workspace symlink: `<workspace>/CLAUDE.md → AGENTS.md`. Created by `awm scope heal` (or `ln -sr <workspace>/AGENTS.md <workspace>/CLAUDE.md`).
- Global Claude Code instructions at `~/.claude/CLAUDE.md`. The shipping global file should tell the agent to read AGENTS.md / `.awm/context.md` for any directory it lands in — Claude Code's own CLAUDE.md walk-up plus the workspace-level symlink make this automatic once wired.

Externally-launched claude in a scope dir auto-loads:

```
~/.claude/CLAUDE.md                          (harness-global)
<workspace>/CLAUDE.md → AGENTS.md            (walk-up; orchestrator persona)
projects/<p>/<scope>/CLAUDE.md → AGENTS.md   (walk-up; project context)
└── @.awm/context.md                         (resolved by Claude Code)
```

## 4. External setup — OpenCode

Required:

- `opencode` CLI on `PATH` (npm: `@opencode/cli` or equivalent).
- MCP config at `~/.config/opencode/opencode.jsonc` pointing at the local `awm-mcp` proxy:

```jsonc
{
  "mcp": {
    "awm": {
      "type": "local",
      "enabled": true,
      "command": ["/home/<you>/lib/miniforge3/envs/awm/bin/awm-mcp"],
      "environment": {
        "AWM_WORKSPACE": "/home/<you>/agentic_workspace",
        "AWM_EXPOSED_HOST": "127.0.0.1",
        "AWM_EXPOSED_PORT": "12100"
      }
    }
  },
  "instructions": [".awm/context.md"]
}
```

For the full MCP catalog (chrome-devtools, ollama, …) in opencode, set `OPENCODE_CONFIG=<workspace>/.awm/mcp-opencode.json` in the shell that launches opencode — that file is the fan-out of the canonical `.mcp.json` produced by `awm_mcp_sync`.

OpenCode reads `AGENTS.md` natively (no symlink needed), and `@.awm/context.md` is resolved as text content of the AGENTS.md it loads.

## 5. AWM-spawned agents

AWM launches agents via rooms — `room_create scopes=[…]` or `room_invite scope=…`. The harness is per-session, persisted on the `agent_sessions.agent_cli` column. Default is `claude`.

To spawn an opencode worker:

```
room_create topic="…" scopes=["proj/scope"] agent_cli="opencode"
```

AWM constructs the argv (`opencode run --format json --dir <wd> [--dangerously-skip-permissions] [--model …]`) and exports `OPENCODE_CONFIG=<workspace>/.awm/mcp-opencode.json` to the subprocess. (Full I/O parity — multi-room input pumping, slash commands — is in progress; the spawn pipeline itself is wired.)

The spawn picks up:

- **MCP catalog** via `--strict-mcp-config --mcp-config <workspace>/.awm/spawn-mcp.json` (claude) or `OPENCODE_CONFIG` (opencode).
- **Workspace + project + scope context** via the `CLAUDE.md` symlinks and `@.awm/context.md` import chain.
- **Permission mode** — `bypassPermissions` by default for worker scopes, configurable per session.

## 6. Verifying setup

```bash
# 1. Symlinks present
ls -l <workspace>/CLAUDE.md projects/*/*/CLAUDE.md

# 2. MCP fan-out produced
awm-mcp call awm_mcp_sync  # or call the tool from an agent
cat <workspace>/.awm/spawn-mcp.json
cat <workspace>/.awm/mcp-opencode.json

# 3. Externally-launched claude sees workspace context
cd <workspace> && claude -p "/context"

# 4. Externally-launched opencode sees workspace context
cd <workspace> && opencode run "list your loaded instructions"

# 5. AWM-spawned opencode worker
awm room create --topic "test" --scope myproj/myscope --agent-cli opencode
```

## 7. Maintenance

Updating any of these files is part of the same edit cycle as the code that surfaced the need (stack change, new MCP, new convention). The `awm/debrief.md` skill enforces this: step 1 is "update AGENTS.md if user-facing behavior changed." Re-run `awm scope heal` if a scope shows up without the wiring.
