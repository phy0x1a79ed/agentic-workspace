# Harness Integration

How to set up an AWM workspace so that **Claude Code** and **OpenCode** — whether spawned by AWM or launched manually inside a scope directory — load the right context docs and see the registered MCP catalog.

Two harnesses are supported as first-class peers:

- **Claude Code** (`claude` CLI) — loads `CLAUDE.md` and `AGENTS.md` from cwd and every parent directory. A session in a scope worktree therefore gets the workspace `AGENTS.md` and the scope's own `AGENTS.md` with no instruction. The workspace `AGENTS.md` startup ritual tells the agent to Read `.awm/context.md`.
- **OpenCode** (`opencode` CLI) — walks `AGENTS.md` upward from cwd only as far as the git worktree root, so it finds the scope's own `AGENTS.md`. Per-scope `.awm/mcp-opencode.json`'s `instructions` array loads the workspace `AGENTS.md` and `.awm/context.md`.

## 1. Context layers (workspace → repo → scope → session)

| Layer | File | Purpose | Source |
|---|---|---|---|
| Workspace | `<workspace>/AGENTS.md` | Universal orientation: paths, startup ritual, MCP tools, rules that lose work. Procedures and internals live beside it in `PROTOCOLS.md` and `ARCHITECTURE.md`, read on demand | Committed; hand-maintained |
| Repo | `<scope>/AGENTS.md` | Project-internal architecture and conventions (e.g. awm Service Hub, vertical-stripe dev). Shared across awm scopes via .bare-worktree topology; lives at scope worktree root per project | Committed; hand-maintained |
| Scope | `<scope>/.awm/context.md` | Per-scope mission brief: purpose, constraints, open questions | Generated by `awm scope create`; gitignored |
| Sessions | `<scope>/.awm/history.md`, `.awm/artifacts.md` | DB-rendered session logs + sibling-scope artifacts | Regenerated by `scope_refresh`; load on demand only |

**Claude Code path.** CC's native walk-up loads tiers 1 and 2. The workspace startup ritual has the agent Read tier 3. Every line of the workspace `AGENTS.md` lands in every session, which is why procedures and internals live in `PROTOCOLS.md` and `ARCHITECTURE.md` instead.

**OpenCode path.** OC walks `AGENTS.md` upward to the worktree root → tier 2 lands without instructions. Per-scope `<scope>/.awm/mcp-opencode.json` carries `instructions: [<abs path to workspace AGENTS.md>, ".awm/context.md"]` → tiers 1 and 3 land on session start without an agent Read. The user-global `~/.config/opencode/AGENTS.md` (a symlink to `~/.claude/CLAUDE.md` on this setup) reinforces the same orientation prose.

History/artifacts are deliberately NOT auto-injected (too large). Agents fetch on demand via `scope_refresh` + Read.

## 2. MCP catalog (registered, advertised even when down)

The canonical MCP registry is `<workspace>/.mcp.json`. AWM fans it out to backend-specific files via the **exporter framework**:

| Exporter | Output | Consumer |
|---|---|---|
| `claude-spawn` | `<workspace>/.awm/spawn-mcp.json` | claude subprocesses launched by AWM (`--strict-mcp-config`) |
| `opencode` | `<workspace>/.awm/mcp-opencode.json` | opencode subprocesses launched by AWM (via `OPENCODE_CONFIG`) — also the base that per-scope `mcp-opencode.json` files overlay `instructions` onto |

Trigger a re-sync from a running agent with the `gateway` domain tool's `mcp-sync` verb (`gateway(verb="mcp-sync")` — `awm_mcp_sync` on CLI/HTTP), or restart the gateway (`awm.service`) — its lifespan hook calls `sync_mcp_configs()` on startup.

**Registration semantics**: every server listed in `.mcp.json` is *advertised* to spawned agents regardless of whether the upstream service is currently running. The agent will see the tool surface; calls fail with a clear error when the service is down. This makes service availability discoverable (an agent knows `chrome-devtools` *exists* even if the Chrome instance hasn't been started yet).

### Adding a new MCP

1. Append the server block to `<workspace>/.mcp.json` (stdio: `command`/`args`/`env`; HTTP: `url`/`type`).
2. Call `gateway(verb="mcp-sync")` (the `awm_mcp_sync` op) — both backends regenerate.
3. New agent spawns pick it up. Already-running agents must reconnect.

See `skill_get path="tools/mcp.md"` for the per-server fields and the `tools/chrome-devtools.md` / `tools/plotly.md` / etc. for service-specific notes.

## 3. External setup — Claude Code

Required:

- `claude` CLI on `PATH` (Anthropic's `claude-code` package).
- Nothing else. CC's native `AGENTS.md` walk-up is the injection surface for the workspace and repo tiers, and the workspace startup ritual covers `.awm/context.md`. No hooks are involved.
- **NO SessionStart hook for context loading.** Earlier wiring put a `context emit` CLI command (since removed) in `~/.claude/settings.json`'s `hooks.SessionStart`; that approach was abandoned after empirical confirmation that Claude Code truncates SessionStart hook output at ~10K chars (head + tail kept, middle dropped), which silently lost the agents-context and scope-context blocks for any scope with combined orientation > 10K. If you find an old hook entry in `~/.claude/settings.json`, remove it.

Externally-launched claude in a scope dir sees, at session start:

```
~/.claude/CLAUDE.md          (user-global)
<workspace>/AGENTS.md        (walk-up: workspace tier)
<scope>/AGENTS.md            (walk-up: repo tier)
```

The agent then Reads `.awm/context.md` as step 2 of the startup ritual.

## 4. External setup — OpenCode

Required:

- `opencode` CLI on `PATH` (npm: `@opencode/cli` or equivalent).
- MCP config at `~/.config/opencode/opencode.jsonc` pointing at the local `awm-mcp` proxy:

```jsonc
{
  "mcp": {
    "awm": {
      "type": "local",
      "enabled": true,
      "command": ["/home/<you>/lib/miniforge3/envs/awm/bin/awm-mcp"],
      "environment": {
        "AWM_WORKSPACE": "/home/<you>/agentic_workspace"
      }
    }
  }
}
```

- Global rules at `~/.config/opencode/AGENTS.md` (typically a symlink to `~/.claude/CLAUDE.md` to keep CC + OC instructions in lockstep).

In each scope, `awm scope create` writes `<scope>/.awm/mcp-opencode.json` with:

```jsonc
{
  "instructions": [
    "/home/<you>/agentic_workspace/AGENTS.md",
    ".awm/context.md"
  ],
  "mcp": { /* fanned out from workspace .mcp.json */ }
}
```

OpenCode resolves the absolute workspace `AGENTS.md` path and the cwd-relative `.awm/context.md` at startup, loading both as system instructions. Tier 2 (the scope's own `AGENTS.md`) is found by OC's native walk-up — listing it here too would double-inject.

For OC to pick up the per-scope file, launch with `OPENCODE_CONFIG=<scope>/.awm/mcp-opencode.json`.

## 5. Sessions started by awm

awm starts Claude Code sessions through `cx start` (a background `claude --bg` job in a scope's worktree). The session loads context the same way a manual launch does: CC's native `AGENTS.md` walk-up for the workspace and repo tiers, and the startup ritual's Read for `.awm/context.md`. awm no longer spawns OpenCode workers; launch `opencode` by hand with `OPENCODE_CONFIG` as in §4.

### Context loading — no CLI command

There is no `context emit` (or equivalent) CLI command — the prior `awm`-level utility was removed. The 3-tier context is loaded directly by each harness, not bundled by AWM tooling:

- **Claude Code** loads both `AGENTS.md` tiers by native walk-up and Reads `.awm/context.md` at the startup ritual (§3).
- **OpenCode** picks up the scope `AGENTS.md` via native walk-up and the workspace `AGENTS.md` + `.awm/context.md` via the per-scope `mcp-opencode.json` `instructions` array (§4).

No user-level harness hook injects context either — the prior SessionStart hook was removed (see §3).

## 6. Verifying setup

```bash
# 1. NO SessionStart hook present (the prior wiring is gone)
jq '.hooks.SessionStart // "absent"' ~/.claude/settings.json
# expect: "absent"

# 2. The workspace AGENTS.md startup ritual names .awm/context.md
grep -n "context.md" <workspace>/AGENTS.md

# 3. MCP fan-out produced
awm-mcp call awm_mcp_sync       # or call the tool from an agent
ls <workspace>/.awm/spawn-mcp.json <workspace>/.awm/mcp-opencode.json

# 4. Per-scope opencode instructions include the workspace AGENTS.md + .awm/context.md
jq .instructions <workspace>/projects/<p>/<scope>/.awm/mcp-opencode.json
# expect: ["<abs path>/AGENTS.md", ".awm/context.md"]

# 5. Externally-launched claude has both AGENTS.md tiers loaded
cd <workspace>/projects/<p>/<scope> && claude -p "List the AGENTS.md files loaded into your context, by absolute path."
# expect: <workspace>/AGENTS.md and <scope>/AGENTS.md

# 6. Externally-launched opencode sees the instructions
cd <workspace>/projects/<p>/<scope> && opencode run "list your loaded instructions"
```

## 7. Maintenance

Updating any of these files is part of the same edit cycle as the code that surfaced the need (stack change, new MCP, new convention). The `debrief` skill enforces this: its first step corrects a doc the change made wrong.

**`awm scope heal`** is the cleanup pass — it enforces the canonical per-scope shape across all active scope worktrees:

- regenerates `<scope>/.awm/mcp-opencode.json` with the current MCP fan-out + `instructions` array
- strips trailing `@.awm/context.md` import lines from tracked `AGENTS.md` (legacy artifact)
- deletes scope-local `AGENTS.md` if untracked (template chrome from the legacy wiring)
- deletes `CLAUDE.md` if it's a symlink to `AGENTS.md` or otherwise untracked (legacy)
- back-fills `.awm/context.md` if missing

Idempotent. Use `awm scope heal --dry-run` to preview.

The native `debrief` skill (`~/.claude/skills/debrief/`) — the full debrief protocol.
